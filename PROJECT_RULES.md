# Project Rules

## General Principles

- Follow all project documentation before implementing any feature.
- Never change the architecture without approval.
- Never remove existing functionality.
- If a requirement is ambiguous, ask instead of assuming.

---

## Development Rules

- Implement only the requested feature.
- Keep modules independent.
- Separate UI, business logic, and data access.
- Avoid duplicate code.
- Prefer composition over duplication.

---

## Code Quality

- Follow PEP 8.
- Use type hints.
- Add docstrings to all public functions.
- Handle exceptions gracefully.
- Use logging where appropriate.

---

## Testing

- Every new module should include tests.
- Do not mark work complete without verifying it.

---

## Documentation

- Update documentation when architecture changes.
- Explain important technical decisions.

---

## AI Behaviour

Before writing code:

1. Explain the implementation plan.
2. List assumptions.
3. Identify possible risks.
4. Wait for confirmation if major architectural changes are required.

Never generate unnecessary code.

Focus on maintainability, readability, and scalability.
